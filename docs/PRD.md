# Orion Assistant iOS PRD

## 1. 产品概述

- 产品临时名：`Orion Assistant`
- 产品定位：面向个人用户的 iPhone 私人助理 App，以 LLM 为交互核心，深度整合系统日历、提醒事项、地图与票据处理能力，帮助用户完成日程安排、出差管理、费用归集与行程规划。
- 目标平台：iOS 18+，SwiftUI 原生开发。
- 设计原则：
  - 优先使用系统能力，减少重复造轮子
  - 所有 AI 建议必须可确认、可追溯、可撤销
  - 关键信息以时间线、任务流、费用流三条主线组织
  - 优先单人高频使用场景，而不是团队协作

## 2. 核心用户

### 2.1 用户画像

- 高频商务出行用户：经常安排会议、航班、高铁、酒店与报销
- 知识工作者：希望用自然语言创建日程、提醒和待办
- 自我管理型用户：需要统一管理时间、任务、费用和路线

### 2.2 关键痛点

- 日历、提醒事项、票据、路线分散在多个 App 内
- 输入日程繁琐，无法通过一段自然语言直接生成计划
- 发票和消费票据难以结构化归档
- 出差前后需要反复手工核对行程、预算、报销状态
- LLM 给建议但缺少系统级执行能力

## 3. 产品目标

### 3.1 业务目标

- 成为用户的个人时间与出差中枢
- 提供从理解意图到执行系统动作的完整闭环
- 通过结构化费用和行程管理，提升商务场景留存

### 3.2 用户目标

- 30 秒内通过对话完成一项复杂日程创建
- 一次拍照或导入即可完成票据解析和费用归类
- 在单个行程卡片内查看会议、交通、住宿、预算与提醒

### 3.3 成功指标

- 首次授权完成率：> 70%
- 日程创建成功率：> 90%
- AI 建议被采纳率：> 45%
- 发票解析字段完整率：> 85%
- 出差行程创建后 7 日内二次打开率：> 50%

## 4. 功能范围

### 4.1 MVP 范围

- LLM 助理对话
- 自然语言创建日历事件
- 自然语言创建提醒事项
- 从一段文本中拆解多个日程和提醒
- 系统日历与提醒事项双向读取
- 发票拍照、OCR、字段结构化
- 差旅费用管理与报销状态追踪
- 地点识别、通勤时间估算、路线建议
- 出差行程容器：聚合会议、交通、住宿、费用、提醒

### 4.2 暂不进入 MVP

- 团队协同与审批流
- 企业 ERP/财务系统直连
- 邮件自动抓取行程单
- iPad / macOS 专项适配
- Siri / Apple Intelligence 扩展

## 5. 主要使用场景

### 场景 A：一句话安排完整日程

用户输入：
`后天下午两点到五点在浦东机场附近安排和客户的会议，并提前一小时提醒我出发。`

系统行为：

- 解析时间、地点、时长、提醒要求
- 若缺信息，追问会议主题或联系人
- 拉取当前位置或默认出发地
- 估算通勤时间并建议出发提醒
- 生成日历事件与提醒事项，等待用户确认

### 场景 B：生成出差计划

用户输入：
`下周去杭州出差两天，周二上午客户拜访，周三下午回上海，帮我排一下。`

系统行为：

- 生成出差草案
- 自动创建出差行程容器
- 产生日历安排、提醒清单、预估交通节点
- 形成预算分类：交通、住宿、餐饮、其他

### 场景 C：发票解析与费用归集

用户操作：
拍摄出租车票据或酒店发票

系统行为：

- OCR 识别票据文本
- 结构化提取金额、日期、商户、税额、票据类型
- 自动建议归类到对应出差或月度费用集
- 标记报销状态：待提交、处理中、已报销

### 场景 D：会前出发与路线规划

系统行为：

- 检测即将到来的日程
- 根据地点和当前时间给出出发建议
- 提供驾车、打车、步行、公共交通的时间预估
- 必要时创建新的提醒事项

## 6. 信息架构

底部四主导航：

- 今日：当日时间线、提醒、即将出发、智能建议
- 助理：LLM 对话、建议确认、历史上下文
- 行程：出差计划、路线、交通节点、预算
- 费用：发票、费用项、报销状态、月度统计

全局入口：

- 顶部快速录入
- 相机扫描
- 系统分享导入
- 小组件与通知跳转

## 7. 功能详细需求

### 7.1 LLM 助理

- 支持文本输入，后续预留语音入口
- 上下文分层：
  - 会话上下文
  - 用户偏好
  - 日历与提醒只读上下文
  - 当前出差上下文
- LLM 输出不直接写系统数据，必须经过动作层转译
- 所有可执行动作以卡片形式展示：
  - 创建事件
  - 创建提醒
  - 生成行程
  - 添加费用
  - 规划路线

### 7.2 日历集成

- 读取系统日历列表
- 支持选择写入目标日历
- 创建、更新、删除 App 创建的事件
- 支持开始时间、结束时间、全天、地点、备注、提醒
- 检测与现有事件冲突并提示

### 7.3 提醒事项集成

- 读取系统提醒列表
- 写入指定提醒清单
- 支持截止时间、优先级、备注、子任务
- 支持将日程关联提醒自动生成

### 7.4 智能排程

- 从自然语言提取时间实体与约束条件
- 结合已有日程检测可用时间段
- 支持推荐候选时段
- 冲突情况下给出 2 到 3 个备选方案

### 7.5 票据与发票

- 输入方式：拍照、相册导入、PDF 导入
- 识别信息：
  - 商户名
  - 票据类型
  - 开票日期
  - 金额
  - 税额
  - 城市
  - 关联出差
- 允许用户手工修正识别结果
- 保留原始影像与识别版本

### 7.6 费用管理

- 费用分类：交通、住宿、餐饮、接待、办公、其他
- 状态：待整理、待提交、报销中、已报销、驳回
- 关联维度：
  - 出差
  - 日程
  - 票据
  - 支付方式
- 提供月度和单次出差统计

### 7.7 路线规划

- 地点解析与标准化
- 估算通勤时间
- 生成推荐出发时间
- 将路线建议写入提醒或事件备注
- 后续可扩展实时路况

## 8. 非功能需求

- 本地优先，敏感信息默认本地存储
- 权限最小化，分场景授权
- AI 响应超时降级为普通手动创建流程
- 票据图片加密存储
- 所有 AI 生成结果保留操作日志
- 支持深色模式与动态字体
- 支持离线查看已同步的日程、提醒、费用

## 9. 系统权限

- `EventKit`：日历与提醒事项
- `PhotosUI`：导入票据图片
- `VisionKit / Vision`：文档扫描与 OCR
- `MapKit / CoreLocation`：地点解析与路线建议
- `UserNotifications`：通知提醒

## 10. 风险与约束

- LLM 对时间语义和中文自然语言的解析可能存在歧义
- 系统日历与提醒的修改权限受用户授权影响
- OCR 对低清晰度票据识别效果不稳定
- 地图与路线依赖第三方或系统服务返回质量
